## Verdict

The product direction and broad phase order are good: MRT as canonical
output, parser 0.20 upgrade first, `ipnet-trie`, raw-message retention, and
immutable-rkyv-plus-MRT-replay are all sound choices. However, Phase 2 lacks
a sufficiently precise BMP/RIB state model, and the proposed event-time /
archive behavior can produce incorrect or overwritten segments under normal
delayed/out-of-order BMP delivery. These must be resolved before
implementation starts.

## BLOCKER findings

### 1. BMP RIB state is not separated by policy plane / peer identity
- References: plan Phase 2 mapping `:108-118`; RIB design `:153-178`; scale
  design `:220-223`. Parser support:
  `bgpkit-parser/src/parser/bmp/messages/headers.rs:195-279`.
- The plan unconditionally maps Route Monitoring to an `Adj-RIB-In` trie.
  That is only correct for **pre-policy Adj-RIB-In**. BMP's per-peer header
  distinguishes pre/post-policy (L flag), Adj-RIB-In/Out (O flag), and peer
  type (Global, RD, Local, Local-RIB). A router can send both pre- and
  post-policy streams for the same BGP peer; keying only on
  "router, peer, AFI/SAFI" merges different RIBs. Peer IP alone also
  collides across VRFs/RDs or repeated peers.
- Fix: canonical feed key = router identity + connection generation +
  peer_type + peer_distinguisher + peer_ip + peer_asn + peer_bgp_id + plane
  {pre_in, post_in, adj_out, local_rib} + AFI/SAFI. v1 accepts only `pre_in`
  by default; other planes are archived separately or quarantined.

### 2. EoR-to-RIB design cannot safely produce the proposed collector files
- References: plan RIB design `:163-178`; `src/archive/mod.rs:148-193`;
  `src/archive/snapshot.rs:65-128`.
- Per-peer EoR dumps all target the same `rib.YYYYMMDD.HHMM` path and
  clobber via rename; a collector RIB is one coherent snapshot across peers
  with a single peer-index table. `SnapshotRoute` is one route/peer and
  `build_table_dump_v2` writes one `RibAfiEntries` per route instead of
  grouping entries per prefix.
- Fix: per-router snapshot coordinator: track eligible feeds, EoR completion
  per feed/AFI, freeze all tries into one dump on explicit policy or
  timeout, one peer-index table, group paths by (AFI, SAFI, prefix), no
  periodic RIB until a valid baseline exists.

### 3. Event-time file selection is unsafe for delayed, zero, or reordered PDUs
- References: plan `:117-118`; `src/archive/mod.rs:114-128,302-336`;
  `src/archive/writer.rs:134-147`; BMP timestamps can be zero
  (`headers.rs:229-232`).
- `ingest_update` selects the writer from `update.timestamp`; late PDUs
  reopen sealed buckets, zero timestamps route to 1970, and `File::create`
  plus rename can replace previous output.
- Fix: separate record event time from partition/seal time. Partition by
  monotonic ingestion clock or event-time watermark with allowed lateness;
  sealed segments never reopen; late data goes to bounded late segments with
  a deterministic suffix; test delayed/reordered/zero-timestamp/boundary
  cases.

## MAJOR findings

4. Peer Up/Down, Termination, and mirroring need explicit feed-lifecycle
   state transitions (Peer Down = implicit full withdraw of that peer's
   routes, invalidate generation; Termination ends all feeds on the
   connection; Route Mirroring is not a re-walk mechanism; MessageLost
   invalidates completeness).
5. ADD-PATH needs a v1 guard: per-AFI/SAFI add-path policy from Peer Up
   OPENs; either `(prefix, path_id)` keys + `*_ADD_PATH` RIB records or
   `ribs_mode=off` for affected feeds with raw updates retained.
6. Capability statement overstated: capability-less OPEN establishes plain
   IPv4 BGP fine; the real requirement is advertise + validate the
   intersection (MP-BGP, AS4, route-refresh, graceful-restart, extended
   message, add-path).
7. Raw preservation needs a pass-through BGP4MP envelope encoder that
   writes original frame bytes unchanged; current path re-encodes from
   parsed structs (can normalize wire form).
8. Backpressure wording wrong: TCP stall is not router re-send. Use bounded
   channels + `send().await`, stop reading that connection on full, define
   overload limits; on loss/queue-abort/MessageLost increment durable
   counters, mark feed generations incomplete, require new Peer Up + EoR
   baseline before derived RIBs resume.
9. Spill durability contract incomplete: need a per-router replay manifest
   (baseline RIB path/checksum, feed key/generation, update segment range,
   watermark, pin count); updates must be durable before eviction (seal
   segment or WAL); retention must pin replay ancestry; rkyv image remains
   optional cache acceleration only.
10. Memory figures inconsistent (raw UPDATE bytes per prefix in Phase 1 vs
    u32 interner id in fleet section; 50-peer math is ~3-6 GiB not 4-8 GB).
    Fix the trie value model (`{attribute_id, last_change_ts, path_id?}`),
    add a benchmark gate before quoting fleet numbers.
11. Per-router archives need a real config hierarchy: `[bmp]` listener +
    `[[bmp.routers]]` keyed by trusted source identity, per-router
    `collector_id`, view/plane policy, archive overrides; never derive
    filesystem identity from untrusted sysName. Daemon currently builds one
    ArchiveService.
12. Trigger semantics: per-trigger delivery records keyed by checksum +
    trigger id + attempt with pending/running/acknowledged/unknown states;
    `unknown` is retriable at-least-once; completion policy
    (local-finalized | all-required | named set); replication events are
    per-destination, no aggregate event exists yet.
13. Path traversal: reject absolute/root/prefix paths, `..`, empty
    filenames before rendering; validate collector_id charset; component-
    based containment checks under roots; replicator joins manifest-relative
    paths without revalidation. Examples must use `[REDACTED]`, avoid
    `0.0.0.0` defaults, pin image digests, and not promise TCP-AO (code
    implements TCP-MD5 only).

## MINOR findings

14. Say "RouteViews/RIS-compatible MRT naming and record types", not
    "identical"; keep manifests with source, plane, completeness, timestamp
    source, config version.
15. Global BGP listener needs peer matching before state mutation, collision
    policy, v4/v6 bind design, rejected-connection observability.
16. Negative tests required before BMP phase: no RIB before baseline,
    malformed UPDATE disposition, Peer Down clears routes, interrupted EoR
    produces no complete dump, duplicate Peer Up starts a new generation,
    per-AFI/SAFI completion independence.

## What is already sound

- Parser 0.15 -> 0.20 with fallible encoders is necessary and correct.
- Dual-stack archive types conversion is necessary (currently IPv4-only).
- Corrected rkyv rule (frozen snapshots + MRT replay, no mutable rkyv trie).
- Storage arithmetic is sound once labeled workload-specific.

## Top 3 changes before implementation

1. Write the BMP feed-state and snapshot-coordinator specification.
2. Redesign ingestion/archive ordering around raw frames and time.
3. Make fleet and security claims implementation-backed.
